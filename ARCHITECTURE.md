# Architecture: app-common-go

**Module:** `github.com/redhatinsights/app-common-go`

This document is the authoritative technical reference for the internal design of `app-common-go`. See [README.md](./README.md) for installation and usage, and [AGENTS.md](./AGENTS.md) for contributor workflow guidance.

---

## Overview

`app-common-go` is a single-purpose Go library: it reads the JSON configuration file produced by the [Clowder operator](https://github.com/RedHatInsights/clowder) and exposes that configuration to application code through typed Go structs and pre-indexed lookup maps. The library has no transitive runtime dependencies and is intentionally narrow in scope.

The entire library lives in one package: `pkg/api/v1`. There is no sub-package hierarchy, no interface layer, and no plugin mechanism. The design prioritises simplicity and minimal surface area over extensibility.

## Package: `pkg/api/v1`

This is the only package in the module. It is imported by consuming applications as:

```go
import v1 "github.com/redhatinsights/app-common-go/pkg/api/v1"
```

The package is split into two source files with distinct responsibilities.

### `types.go` — Auto-generated Type Definitions

**Do not edit by hand.** This file is regenerated by `sync_config.sh` using
[`go-jsonschema`](https://github.com/atombender/go-jsonschema) from `schema.json`.

#### Root type

| Type | Description |
|---|---|
| `AppConfig` | Root struct for the entire Clowder config document |

#### Sub-configuration types

| Type | JSON field | Required fields | Notes |
|---|---|---|---|
| `DatabaseConfig` | `database` | `name`, `username`, `password`, `hostname`, `port`, `adminUsername`, `adminPassword`, `sslMode` | `rdsCa` is optional (absent when RDS TLS is not configured) |
| `KafkaConfig` | `kafka` | `brokers`, `topics` | Wraps lists of `BrokerConfig` and `TopicConfig` |
| `BrokerConfig` | `kafka.brokers[]` | `hostname` | `port`, `cacert`, `authtype`, `sasl`, `securityProtocol` are all optional |
| `KafkaSASLConfig` | `kafka.brokers[].sasl` | none | All fields optional; used when `authtype == "sasl"` |
| `TopicConfig` | `kafka.topics[]` | `name`, `requestedName` | `requestedName` is the app-defined name; `name` is the actual Kafka topic name |
| `ObjectStoreConfig` | `objectStore` | `hostname`, `port`, `tls` | Global S3-compatible store config |
| `ObjectStoreBucket` | `objectStore.buckets[]` | `name`, `requestedName` | Per-bucket credentials may differ from global store credentials |
| `FeatureFlagsConfig` | `featureFlags` | `hostname`, `port`, `scheme` | `scheme` is a validated enum: `"http"` or `"https"` |
| `InMemoryDBConfig` | `inMemoryDb` | `hostname`, `port` | Represents Redis/Valkey connections |
| `LoggingConfig` | `logging` | `type` | Required at the root level; `cloudwatch` sub-object is optional |
| `CloudWatchConfig` | `logging.cloudwatch` | `accessKeyId`, `secretAccessKey`, `region`, `logGroup` | Only present when logging type is `"cloudwatch"` |
| `DependencyEndpoint` | `endpoints[]` | `name`, `hostname`, `port`, `app`, `apiPath` | Public inter-service endpoint; `apiPath` is deprecated in favour of `apiPaths[]` |
| `DependencyEndpointV2` | `endpoints[]` (V2 format) | `uri` | New V2 endpoint format (added Oct 2025) |
| `AppConfigDependencyEndpoints` | — | none | Wrapper struct for V2 public endpoint map format |
| `PrivateDependencyEndpoint` | `privateEndpoints[]` | `name`, `hostname`, `port`, `app` | Same as above but for private (H2C/internal) endpoints; no `apiPath` |
| `AppConfigPrivateDependencyEndpoints` | — | none | Wrapper struct for V2 private endpoint map format |
| `PrometheusGatewayConfig` | `prometheusGateway` | `hostname`, `port` | Pushgateway endpoint for metric forwarding |
| `AppMetadata` | `metadata` | none | Optional operator-injected metadata (app name, env name, deployment images) |
| `DeploymentMetadata` | `metadata.deployments[]` | `name`, `image` | Per-deployment image reference |

#### Enum types

| Type | Valid values | Enforcement |
|---|---|---|
| `BrokerConfigAuthtype` | `"sasl"` | Custom `UnmarshalJSON` rejects unknown values at decode time |
| `FeatureFlagsConfigScheme` | `"http"`, `"https"` | Custom `UnmarshalJSON` rejects unknown values at decode time |

#### Required-field validation pattern

For every struct that has required fields, `go-jsonschema` generates a custom `UnmarshalJSON` method. The pattern is consistent across all types:

```go
func (j *SomeConfig) UnmarshalJSON(b []byte) error {
    var raw map[string]interface{}
    if err := json.Unmarshal(b, &raw); err != nil {
        return err
    }
    if v, ok := raw["requiredField"]; !ok || v == nil {
        return fmt.Errorf("field requiredField in SomeConfig: required")
    }
    // ... additional required field checks ...
    type Plain SomeConfig   // alias breaks the UnmarshalJSON recursion
    var plain Plain
    if err := json.Unmarshal(b, &plain); err != nil {
        return err
    }
    *j = SomeConfig(plain)
    return nil
}
```

The `type Plain T` alias is necessary to avoid infinite recursion: unmarshalling into the alias type uses the default `encoding/json` behaviour rather than calling the custom method again.

Optional fields use Go pointer types (`*string`, `*int`, `*bool`). A nil pointer means the field was absent in the JSON document. Non-pointer types are required fields.

### `config.go` — Config Loader and Runtime State

This file contains all hand-written code in the library.

#### Package-level globals

```go
var LoadedConfig                *AppConfig
var KafkaTopics                 map[string]TopicConfig
var DependencyEndpoints         map[string]map[string]DependencyEndpoint
var PrivateDependencyEndpoints  map[string]map[string]PrivateDependencyEndpoint
var ObjectBuckets               map[string]ObjectStoreBucket
var KafkaServers                []string
```

These globals are populated once, inside the `init()` function, immediately after the package is first imported. They provide O(1) lookups for the most common access patterns:

| Global | Key structure | Value |
|---|---|---|
| `KafkaTopics` | `requestedName` | `TopicConfig` |
| `DependencyEndpoints` | `[appName][deploymentName]` | `DependencyEndpoint` |
| `PrivateDependencyEndpoints` | `[appName][deploymentName]` | `PrivateDependencyEndpoint` |
| `ObjectBuckets` | `requestedName` | `ObjectStoreBucket` |
| `KafkaServers` | — (slice) | `"hostname:port"` strings |

`KafkaTopics` and `ObjectBuckets` are indexed by **requested name** (the name declared in the `ClowdApp` manifest), not the actual name assigned by the operator. This decouples application code from operator-level name mangling.

#### Exported functions

| Function | Signature | Purpose |
|---|---|---|
| `IsClowderEnabled` | `() bool` | Returns `true` when `ACG_CONFIG` env var is set |
| `LoadConfig` | `(filename string) (*AppConfig, error)` | Reads and unmarshals a Clowder JSON file; returns error on I/O or schema violations |

#### Methods on `AppConfig`

| Method | Signature | Purpose |
|---|---|---|
| `RdsCa` | `() (string, error)` | Writes `Database.RdsCa` PEM content to a temp file; returns the file path |
| `KafkaCa` | `(brokers ...BrokerConfig) (string, error)` | Writes the CA cert of the first supplied broker (or first configured broker) to a temp file |
| `KafkaFirstCa` | `() (string, error)` | Convenience wrapper: writes the CA cert of `Kafka.Brokers[0]` to a temp file |

The CA-writing methods exist because TLS libraries in Go require certificate data to be on disk. The library handles the temporary file lifecycle on behalf of the caller. **Callers are responsible for cleaning up returned temp file paths** — the library does not delete them.

The internal helper `writeContent(dir, file string, contentString *string) (string, error)` creates a new temp directory on every invocation and then creates a temp file inside it. Each call produces a unique path; files are never shared between calls.

#### `init()` execution flow

```text
Package imported
    └── init()
        ├── IsClowderEnabled()? → no → return (globals remain nil/zero)
        └── yes
            ├── LoadConfig(os.Getenv("ACG_CONFIG"))
            │     └── os.ReadFile → json.Unmarshal → *AppConfig
            ├── LoadedConfig = result
            ├── Build KafkaTopics   (index: requestedName → TopicConfig)
            ├── Build DependencyEndpoints   (index: app → name → endpoint)
            ├── Build PrivateDependencyEndpoints (index: app → name → endpoint)
            ├── Build ObjectBuckets (index: requestedName → bucket)
            └── Build KafkaServers  (slice: "host:port" per broker)
```

Errors from `LoadConfig` are printed to stdout (`fmt.Println`) and the function returns without panicking. All globals remain at their zero values (`nil`). **There is no retry, no fatal exit, and no error surfacing to the caller** — callers that access `LoadedConfig` without first checking `IsClowderEnabled()` will encounter a nil pointer dereference.

## Configuration Input

The library reads a single JSON document at the path specified by the `ACG_CONFIG` environment variable. The document schema is `pkg/api/v1/schema.json` (JSON Schema Draft-07, `$id: https://cloud.redhat.com/schemas/clowder-appconfig`).

### Required top-level fields

All other top-level fields are optional and pointer-typed in `AppConfig`.

| Field | Go type | Purpose |
|---|---|---|
| `metricsPort` | `int` | Port for Prometheus `/metrics` scraping |
| `metricsPath` | `string` | Path for Prometheus metrics endpoint |
| `logging` | `LoggingConfig` | Logging backend configuration |

### Notable optional fields

| Field | Go type | Notes |
|---|---|---|
| `publicPort` | `*int` | Primary HTTP API port |
| `privatePort` | `*int` | Internal traffic port |
| `webPort` | `*int` | Deprecated alias for `publicPort` |
| `h2cPublicPort` / `h2cPrivatePort` | `*int` | HTTP/2 Cleartext ports |
| `tlsCAPath` | `*string` | Shared CA cert path for inter-app TLS (set when TLS is enabled env-wide) |
| `BOPURL` | `*string` | URL for the Back-Office Proxy service |
| `hashCache` | `*string` | Opaque hash of mounted configMaps/secrets (used for rollout detection) |
| `hostname` | `*string` | External hostname of the deployment |

## Code Generation

`types.go` is generated by [`github.com/atombender/go-jsonschema`](https://github.com/atombender/go-jsonschema) (CLI: `gojsonschema`). The generation workflow is:

```text
Upstream Clowder repo
    └── controllers/cloud.redhat.com/config/schema.json
            │   (downloaded by sync_config.sh via wget)
            ▼
    pkg/api/v1/schema.json
            │   (gojsonschema -p v1 -o types.go schema.json)
            ▼
    pkg/api/v1/types.go
```

`sync_config.sh` orchestrates both steps: it downloads the canonical schema from the Clowder GitHub repository and immediately regenerates `types.go`. There are no intermediate transformation steps. Schema fields map directly to Go struct fields through the generator's default conventions (camelCase JSON tags, pointer types for optional fields).

The generated file carries a `// Code generated by github.com/atombender/go-jsonschema, DO NOT EDIT.` header. The `go:generate` directive is **not** used; regeneration is triggered manually by running `sync_config.sh`.

## Error Handling Conventions

The library uses two distinct error-handling strategies depending on context:

| Context | Strategy | Rationale |
|---|---|---|
| `init()` load failure | Print to stdout, return silently | Avoids panicking the host process at import time; calling code is expected to check `IsClowderEnabled()` |
| `LoadConfig` | Return `(nil, error)` | Allows callers to handle config errors explicitly |
| CA file helpers | Return `("", error)` | Caller must check `err` before using the returned path |
| Schema validation | Return descriptive `fmt.Errorf` from `UnmarshalJSON` | Surfaces field-level required-field violations at decode time |

There is no structured error type or sentinel error value. Error strings are human-readable but not programmatically distinguishable (e.g., callers cannot check `errors.Is(err, ErrNoRdsCa)`).

## Known Tradeoffs and Design Decisions

### Global mutable state

All indexed lookups (`KafkaTopics`, `DependencyEndpoints`, etc.) are package-level variables. This simplifies the consumer API — callers reference `v1.KafkaTopics["name"]` directly rather than threading a config object through their call stack. The tradeoff is that:

- Tests cannot run concurrently if they modify these globals.
- The library cannot manage multiple independent configs in a single process (e.g., for testing purposes, one test fixture affects all tests in the package).
- There is no thread-safety guarantee on writes (writes only happen in `init()`, so reads are safe after package initialisation).

### `init()` side effects

Triggering `init()` at import time means the config is loaded before `main()` runs. This is convenient for library consumers but means errors during config load are silent beyond a `fmt.Println`. Applications that need to respond to config load failures (e.g., exit with a specific code) must call `LoadConfig` themselves and not rely on the `init()` path.

### No pgPass in `DatabaseConfig`

The `pkg/api/v1/testdata/test.json` fixture includes `"pgPass": "testing"` but `DatabaseConfig` in `types.go` has no `PgPass` field. `encoding/json` silently discards unknown fields, so this extra key in the fixture is harmless but indicates a schema drift: the fixture was written against an older schema version or a schema that includes `pgPass`, which the current `schema.json` does not define.

### `KafkaCa` nil-deref risk

`KafkaCa()` (called with no arguments) accesses `LoadedConfig.Kafka.Brokers` directly without first checking that `LoadedConfig` or `LoadedConfig.Kafka` is non-nil (`config.go:101`). If called in an environment where Kafka is not configured, this will panic. The safer `KafkaFirstCa` method includes an explicit nil guard.

### Deprecated fields retained in schema

`DependencyEndpoint.ApiPath` and `AppConfig.WebPort` are retained in the schema (and thus in `types.go`) as deprecated fields. Removing them would be a breaking change for any consumer that references them directly.

### Temp file cleanup is caller responsibility

`RdsCa`, `KafkaCa`, and `KafkaFirstCa` create new temp directories and files on every call with no mechanism to clean them up. Long-running processes that call these methods repeatedly will accumulate temp files. Callers should call `os.Remove` or `os.RemoveAll` on the returned path and its parent directory when done.

## CI

`.github/workflows/package.yml` runs on every push and pull request with two jobs:

**Lint job:** Runs `golangci-lint` with `only-new-issues: true` to catch style violations on every PR.

**Test job:** Runs tests across multiple Go versions (1.18 being the minimum, with newer versions also tested) on both Ubuntu and macOS. Tests run with `-race` flag for race detection and `-coverprofile=coverage.out -covermode=atomic` for coverage collection. No coverage threshold is enforced, but coverage metrics are tracked.
